# 运行与配置指南

本文档回答三件事：**怎么跑起来**、**怎么调整数据文件**、**有哪些要求和注意事项**。

---

## 一、怎么运行

### 1. 准备环境
1. 安装 Python 3.9+：https://www.python.org/downloads/ ，安装时务必勾选 **Add Python to PATH**；
2. 打开命令行（Win 键 → 输入 `cmd` 或 `PowerShell`）；
3. 进入项目目录：
   ```bash
   cd 技术源码
   ```
4. 验证：
   ```bash
   python --version
   ```
   能打印 `Python 3.x` 即成功。

> 模板模式**不需要安装任何第三方库**，直接就能跑。只有 LLM 模式需要 `requests`。

### 2. 三条核心命令

```bash
# ① 跑内置示例（肠胃贴 + 蓝牙耳机，各 5 条）——最快验证一切正常
python -m agent demo

# ② 用你自己的商品生成
python -m agent generate ^
  --product "暖颈贴" ^
  --category "医疗保健" ^
  --price 29.9 ^
  --medical ^
  --points "恒温发热" --points "轻薄无感" ^
  --pains "低头族脖子酸痛" --pains "空调房受凉" ^
  --audience "上班族" ^
  --promo "买二送一" ^
  --count 5 --seed 42 ^
  --out examples/generated --prefix my_product

# ③ 单独检测一段文案是否合规
python -m agent check --text "这款产品根治胃病，全网最低价" --medical
```

结果默认导出 4 种格式：`.md`（可读）/ `.json`（结构化）/ `.csv`（表格）/ `.html`（浏览器打开看效果）。

### 3. LLM 模式（可选）
```bash
# 复制配置模板，填上你的火山方舟 API Key
copy .env.example .env
# 编辑 .env：ARK_API_KEY=你的key

pip install -r requirements.txt

python -m agent generate --product "草本温灸肠胃贴" --medical ^
  --points "草本恒温发热" --points "持续温灸8小时" ^
  --pains "肚子着凉胀气" ^
  --mode llm --count 5
```

## 二、目录地图：哪个文件管什么

| 文件 | 作用 | 你可能会改 |
| --- | --- | --- |
| `data/templates.json` | **爆款结构提示词模板库**：钩子 / 结构 / CTA | ✅ 常改 |
| `data/compliance_rules.json` | **合规引擎**：违禁词、自动替换、合规提示语 | ✅ 常改 |
| `data/products.json` | 内置示例商品（demo 用） | ✅ 常改 |
| `agent/generator.py` | 模板模式的组合逻辑 + 占位符填充 | ⚠️ 加新占位符时才改 |
| `agent/compliance.py` | 合规检测/修正逻辑 | ⚠️ 加新规则作用域时才改 |
| `agent/llm.py` | LLM 模式提示词与调用 | ⚠️ 调提示词时才改 |
| `tests/` | 单元测试（改完跑一遍做回归） | ✅ 加测试 |

**数据文件是智能体的配置核心**：模板库 = 它会说什么；合规规则 = 它不能说什么；商品库 = 它服务的对象。改这三个 JSON，就能把智能体调成你自己的风格。

## 三、数据文件自调（重点）

### 3.1 模板库 `data/templates.json`

结构三层：
```jsonc
{
  "hooks":      [ /* 黄金3秒钩子 */ ],
  "structures": [ /* 脚本结构（分镜骨架） */ ],
  "cta":        [ /* 转化话术 */ ]
}
```

**可用占位符（填充时自动替换为商品信息）**：

| 占位符 | 含义 |
| --- | --- |
| `{商品}` | 商品名 |
| `{价格}` | 售价 |
| `{痛点}` | 随机一条痛点 |
| `{卖点}` | 随机一条卖点 |
| `{人群}` | 目标人群 |
| `{品牌}` | 品牌名 |
| `{背书}` | 信任背书 |
| `{优惠}` | 促销信息 |
| `{限量}` | 随机数字（30-100） |

**加一条自己的钩子**（示例：借势热点型）：
```jsonc
{
  "id": "hot_topic",
  "name": "热点借势",
  "template": "最近大家都在聊的这个，{人群}一定要知道，{优惠}别错过。"
}
```
改完用下面的命令验证能被加载：
```bash
python -m agent templates
```

**注意**：`id` 不能重复；占位符只能用上表里的，出现新占位符会报 `KeyError`。

### 3.2 合规规则 `data/compliance_rules.json`

结构三层：

```jsonc
{
  "banned_words": [
    {
      "id": "规则ID",
      "scope": "all",            // all=所有商品都查；medical=仅医疗商品查
      "pattern": "根治|治愈|药到病除",  // 正则，| 表示"或"
      "severity": "high",
      "message": "提示文案",
      "suggestion": "替换建议"
    }
  ],
  "auto_fix": { "药到病除": "缓解不适" },   // 检测到后自动替换
  "required_disclaimers": { "medical": ["合规提示语1", "合规提示语2"] }
}
```

**加一条规则**（示例：美妆类禁用"美白神器"）：
```jsonc
{
  "id": "cosmetic_claim",
  "scope": "all",
  "pattern": "美白神器|三天变白|永久美白",
  "severity": "high",
  "message": "功效夸大，涉嫌虚假宣传",
  "suggestion": "改为「帮助提亮肤色」等客观表述"
}
```
并在 `auto_fix` 里加：
```jsonc
"美白神器": "帮助提亮肤色"
```

**快速验证**：
```bash
python -m agent check --text "三天变白的美白神器" --medical
python -m agent check --text "本品为日常用品，不能代替药物" --medical   # 应通过
```

**注意**：
- `pattern` 是正则，`|` 是"或"；词越长越靠前，避免短词误伤长词（如先写 `药到病除` 再写 `病除`）；
- `scope` 目前只支持 `all` / `medical`；想加"食品专属规则"这类新作用域，需要改 `agent/compliance.py` 里的过滤逻辑；
- 合规提示语（disclaimers）只在医疗商品上自动附加，且不会被当成违禁词（已处理）。

### 3.3 商品库 `data/products.json`

按字段追加即可：
```jsonc
{
  "name": "暖颈贴",
  "category": "医疗保健",
  "price": 29.9,
  "brand": "XX牌",
  "selling_points": ["恒温发热", "轻薄无感"],
  "pain_points": ["低头族脖子酸痛", "空调房受凉"],
  "target_audience": "上班族",
  "trust_proof": "已通过相关资质备案",
  "promo": "买二送一",
  "medical": true
}
```
验证：
```bash
python -m agent products
python -m agent demo --count 5 --seed 42
```

## 四、调试技巧

| 目的 | 命令 |
| --- | --- |
| 固定随机结果，方便对比修改前后 | `--seed 42`（每次传相同值） |
| 看"修正前"的原始违规问题 | `--no-fix`（只检测不替换） |
| 快速验证某句话是否违规 | `python -m agent check --text "..." --medical` |
| 校验 JSON 语法（改完必做） | `python -m json.tool data\templates.json` |
| 查看模板库当前内容 | `python -m agent templates` |
| 跑全部测试 | `python -m unittest discover -s tests -v` |
| 只跑一个测试文件 | `python -m unittest tests.test_compliance -v` |
| 只跑一个测试用例 | `python -m unittest tests.test_generator.ScriptGeneratorTest.test_generate_count -v` |

**自己加测试**：`tests/` 里的文件是标准 `unittest`，照着现有用例抄一个即可。比如你想保证"新加的钩子一定能被填充"，就把模板写进 `test_templates.py` 的测试里。

## 五、常见报错对照表

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `No module named 'agent'` | 没在项目根目录运行 | 先 `cd` 到 `技术源码` 再执行 |
| `KeyError: 'xxx'` | 模板里用了不存在的占位符 | 只用文档里的 9 个占位符 |
| `JSONDecodeError` / `Expecting value` | JSON 写坏了，或文件不是 UTF-8 | 用 `python -m json.tool` 定位；记事本另存为 UTF-8 |
| `Unexpected UTF-8 BOM` | 旧版记事本保存带 BOM（本项目已兼容） | 代码已用 `utf-8-sig` 读取，确认是最新版本即可 |
| `RuntimeError: LLM 模式需要 requests` | 没装依赖 | `pip install -r requirements.txt` |
| `缺少 API Key` | 没配 `.env` | 复制 `.env.example` 为 `.env` 填 key（程序会自动读取） |
| HTTP 401/403 | Key 不对或模型未开通 | 检查火山方舟控制台的 Key 与模型 ID |
| 终端中文乱码 | Windows 控制台编码问题 | PowerShell 先执行 `$env:PYTHONIOENCODING="utf-8"` |
| `python 不是内部或外部命令` | 没装 Python 或没加 PATH | 重装时勾选 Add Python to PATH |

## 六、注意事项清单

1. **改数据文件前先备份**（复制一份到别处）；
2. **新增占位符要同步改代码**：`agent/generator.py` 的 `_fill()` 里的 `kwargs`，加上对应的填充值；
3. **正则别误伤**：短词会匹配长词的片段，比如规则里只写 `第一`，会把"第一时间"也拦掉——写完整词组；
4. **demo 会覆盖 `examples/demo/`**：重跑 `demo` 会重新生成，想保留旧样例就改名；
5. **别把真实 API Key 提交到 GitHub**：`.gitignore` 已忽略 `.env`，但记得 `git add` 前检查；
6. **医疗 vs 非医疗**：`medical: true` 的商品会自动附加合规提示语并启用功效强校验，非医疗商品不会；
7. **生成结果每次不同**：想复现就用 `--seed`；改过模板后对比效果，固定同一个 seed 才公平；
8. **Python 版本**：需要 3.9+（用到了较新的类型语法），3.8 及以下会报语法错误。

## 七、改完一轮的自检清单

1. `python -m json.tool data\templates.json`（每个改过的 JSON 都跑一遍）
2. `python -m agent templates`（模板库正常列出）
3. `python -m agent check --text "你的测试文案" --medical`（新规则生效）
4. `python -m agent demo --count 5 --seed 42`（整体生成正常）
5. `python -m unittest discover -s tests`（回归测试全绿）
